**Status: Final Testing has NOT started.** Every case is `NOT_RUN` until it is actually performed on the final

are re-run on the final release candidate.

## How to record a result
1. Run the case on the final build (release signed with the owner's key unless the case says debug).
2. Save the evidence in `testing/evidence/` (screenshots, videos, logs; no tokens, keys or private content).
3. Record it: `python3 scripts/testplan.py set CAP-01 PASS --build 1.0.0 --device "<phone model, Android version>" --evidence testing/evidence/CAP-01.png`
   (`FAIL`/`BLOCKED` need `--notes`). Or edit the CSV directly, then run `python3 scripts/testplan.py check`.
4. `python3 scripts/testplan.py gate` passes only when every case is PASS (or SKIPPED with a reason).
5. A failed case gets a bug fix, a new build, and the affected cases (plus AUTO) are run again.

Order: AUTO → DEV → CAP/OCR → OFF → SRCH → AI → OAUTH → BAK → NOT → EXP → SEC → DATA → FEAT → A11Y → PERF → FLOW.
Safety: back up before BAK/DATA cases; never type tokens or keys anywhere except the app's own fields;
Notion cases must not change the Master Database schema or the 15 legacy entries.
